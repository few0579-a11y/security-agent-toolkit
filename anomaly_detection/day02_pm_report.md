## 5교시 · 정규화된 이벤트를 표로 읽고 실패만 골라 세기

### 문제 5-1 · 정규화된 이벤트 표를 읽어 실패한 이벤트를 소스별로 세기

- (가) 실행한 출력 전체를 붙여 넣고, 표의 행 수와 열 수, 성공과 실패 개수, 실패한 이벤트의 소스별 개수를 적어 주세요.
  - 쓸 내용: ① 출력 전체(코드 상자에 붙여 넣기) ② 행 수 · 열 수와 성공 · 실패 개수 ③ 소스별 실패 개수
  - 답:
      전체 이벤트는 57개(57행 6열)이며, 성공 34개, 실패 23개이다. 실패 이벤트의 소스별 개수는 web 13개, server 9개, saas 1개이다.

```--- 단계 1: 표 크기(행 수, 열 수)와 처음 3개 시각
(57, 6)
2026-11-02 02:14:08
2026-11-02 09:01:05
2026-11-02 09:01:06
--- 단계 2: 성공 · 실패별 개수
result
성공    34
실패    23
Name: count, dtype: int64
--- 단계 3: 실패한 이벤트 23 개의 소스별 개수
source
web       13
server     9
saas       1
Name: count, dtype: int64
--- 단계 4: 전체 이벤트의 소스별 개수
source
web       28
server    15
saas      14
Name: count, dtype: int64
```

- (나) 🔍 실패 개수만 보면 web 이 가장 많습니다. 그렇다면 web 이 가장 문제가 큰 소스라고 말할 수 있을까요? 단계 4의 전체 이벤트 수와 함께 보고 이유를 적어 주세요.
  - 쓸 내용: ① 말할 수 있는지 없는지 ② 소스마다 전체 이벤트 수가 다르다는 것을 근거로 한 이유
  - 답:
      web의 실패 횟수는 13개로 가장 많지만, 이것만으로 가장 문제가 크다고 판단할 수 없다. 전체 이벤트 대비 실패율을 비교하면 web은 13/28(약 46.4%), server는 9/15(60%), saas는 1/14(약 7.1%)이다. 따라서 실패 건수는 web이 가장 많지만 실패율은 server가 가장 높다. 소스별 전체 이벤트 수가 다르므로 건수와 비율을 함께 확인해야 한다.

- (다) 🔍 web 이벤트에는 `user` 가 비어 있습니다. 사용자 이름으로 실패를 세려 할 때 web 의 실패 13개는 어떻게 될지 예상하고, 사용자 대신 어떤 열을 보면 같은 대상이 반복했는지 알 수 있을지 이유와 함께 적어 주세요.
  - 쓸 내용: ① 사용자 이름으로 셀 때 web 실패 13개가 어떻게 될지 ② 대신 볼 열과 그 이유
  - 답:
      web 로그에는 user 값이 없으므로 사용자별 집계에서 web 실패 13개가 제외될 수 있다. 대신 ip 열을 확인하면 동일한 IP 주소에서 실패 요청이 반복되었는지 파악할 수 있다. 다만 IP 주소만으로 동일한 사용자라고 확정할 수는 없다.

## 6교시 · 실패를 사용자별 · 시간대별로 묶어 세고 저장하기

### 문제 6-1 · 실패한 이벤트를 사용자별 · 시간대별로 묶어 세고 CSV 로 저장하기

- (가) 실행한 출력 전체를 붙여 넣고, 실패가 가장 많은 사용자와 횟수, 실패가 가장 많이 난 시간대와 횟수, 저장된 행 수를 적어 주세요.
  - 쓸 내용: ① 출력 전체(코드 상자에 붙여 넣기) ② 실패가 가장 많은 사용자와 횟수 ③ 가장 많이 난 시간대와 횟수 ④ 저장된 행 수
  - 답:
      실패가 가장 많은 사용자는 dami로 4건이다. 실패가 가장 많이 발생한 시간대는 9시로 13건이며, failed_events.csv 파일에 실패 이벤트 23건을 저장하고 재읽기로 확인했다.

```
 python day02_6-1_run.py
--- 단계 1: 사용자별 실패 횟수
user
dami       4
gaeun      3
seoyeon    2
jiwoo      1
dtype: int64
--- 단계 2: 시간대별 실패 횟수
hour
2      1
9     13
10     3
11     5
18     1
dtype: int64
--- 단계 3: 저장한 파일 failed_events.csv
저장된 행 23 개
```

- (나) 🔍 시간대별 결과에서 실패가 가장 많이 난 시간대의 개수를 보세요. 이 개수는 5교시 단계 3의 어느 소스 개수와 같은가요? 그 실패가 어느 소스에서 났는지 적고(근거는 숫자가 같다는 것까지 쓰면 됩니다), 이어서 확인할 것도 적어 주세요.
  - 쓸 내용: ① 많이 난 실패가 어느 소스에서 난 것인지와 그 근거 ② 이어서 확인할 것
  - 답:
      9시에 발생한 실패는 13건이며, 5교시에서 확인한 web의 실패 13건과 같다. CSV 파일을 다시 읽어 hour가 9인 이벤트를 source별로 집계한 결과, 13건 모두 web에서 발생했음을 확인했다. 이어서 같은 IP 주소에서 로그인 실패가 반복되었는지, 실패 직후 성공한 요청이 있었는지 확인할 필요가 있다.

- (다) 🔍 사용자별 실패 횟수를 모두 더하면 실패한 이벤트 전체보다 적습니다. 몇 개가 모자라고 왜 모자란지 적어 주세요. 그리고 이 차이를 모르고 사용자별 숫자만 보면 어떤 잘못된 판단을 할 수 있을지도 적어 주세요.
  - 쓸 내용: ① 몇 개가 모자란지 ② 모자란 이유 ③ 모르고 넘어가면 생기는 잘못된 판단
  - 답:
      사용자별 실패 횟수의 합계는 4+3+2+1=10건으로 전체 실패 23건보다 13건 적다. web 로그에는 user 값이 없으며, pandas의 groupby()는 기본적으로 결측값을 제외하기 때문이다. 이를 모르고 사용자별 집계만 보면 전체 실패가 10건뿐이라고 잘못 판단하거나, 웹 서버에서 발생한 13건의 실패를 놓칠 수 있다.
