### 문제 2-1 · 내 IP 를 2진수로

- (가) 두 번째 파일(`warmup_2_1b.py`, 내 IPv4 주소)의 출력 네 줄:

    192 11000000
    168 10101000
    0 00000000
    15 00001111


- (나-1) `format(number, "08b")` 가 마디 하나의 10진수를 어떤 형태의 글자로 바꾸는지, 내 출력 한 줄을 예로 들어 설명하세요.
  - 답: 
  10진수를 8자리의 2진수 문자열로 변환한다. 8자리가 되지 않으면 앞에 0을 채운다. 예를 들어 내 IP주소의 마지막 마디인 15는 2진수로 1111이지만, 8자리에 맞추면 00001111로 출력된다.


- (나-2) `"08b"` 에서 `08` 을 빼고 `"b"` 만 쓰면 `10` 은 어떻게 출력되나요?
  - 답:
  1010으로 출력된다. "08b"를 사용하면 00001010으로 출력되지만, "b"만 사용하면 앞의 0을 채우지 않고 필요한 자리만 출력한다.


- (나-3) 마디마다 8자리로 맞춰 써야 하는 이유를 설명하세요.
  - 답:

  IPv4 주소는 8비트씩 4개의 마디로 구성되어 있다. 각 마디를 8자리로 맞추면 서브넷 마스크와 비트의 위치를 정확하게 대조할 수 있고, 네트워크 주소를 계산할 때 혼동을 줄일 수 있다.



- (다-1) IPv4 주소가 32비트라는 것과 마디 하나가 `0` ~ `255` 사이의 값만 가진다는 것은 어떻게 이어지나요? 마디 수와 비트 수를 근거로 설명하세요.
  - 답:


  IPv4 주소는 4개의 마디로 구성되어 있고, 각 마디는 8비트이므로 총 32비트이다. 1비트에는 0 또는 1이 들어갈 수 있기 때문에 8비트로는 2⁸ = 256가지 값을 표현할 수 있다. 0부터 세기 때문에 각 마디의 최솟값은 0, 최댓값은 255이다.



- (다-2) 32비트로 만들 수 있는 주소의 개수: 

 2³² = 4,294,967,296개 (약 43억 개)

- (다-3) 그 개수가 나오는 계산 과정을, 비트 한 자리에 들어갈 수 있는 값의 가짓수와 자리 수를 넣어 단계별로 설명하세요.
  - 답:

      1비트에는 0과 1, 총 2가지 값이 들어갈 수 있다. 따라서 8비트로는 2⁸ = 256가지 값을 표현할 수 있다. IPv4는 8비트짜리 마디가 4개이므로 각 마디에서 가능한 256가지 값을 조합하면 된다.

      256 × 256 × 256 × 256 = 2³² = 4,294,967,296개가 된다.



- (다-4) 이 수의 한계가 사설 IP 와 NAT 를 쓰게 된 것과 어떻게 이어지는지 설명하세요.
  - 답:


      IPv4 주소는 약 43억 개로 한정되어 있어 인터넷에 연결되는 모든 기기에 각각 공인 IP 주소를 할당하기 어렵다. 그래서 가정이나 회사 내부에서는 사설 IP 주소를 사용하고, 인터넷에 접속할 때는 공유기나 라우터의 NAT 기능을 이용해 사설 IP를 공인 IP로 변환한다. 이를 통해 여러 기기가 하나의 공인 IPv4 주소를 공유할 수 있어 공인 IP 주소의 부족 문제를 완화할 수 있다.

## 3교시 · 서브넷 마스크 · CIDR

### 문제 3-1 · 내 서브넷 마스크 읽기

- (가-1) 내 서브넷 마스크 · CIDR · 주소 수 · 쓸 수 있는 수:

        서브넷 마스크: 255.255.255.0

        CIDR: /24

        전체 주소 수: 256개

        장비에 할당 가능한 주소 수: 254개

- (가-2) 내 IPv4 주소의 망 부분 · 장비 부분:

        IPv4 주소: 192.168.200.48

        망 부분: 192.168.200 (앞 24비트)

        장비 부분: 48 (뒤 8비트)

- (나-1) 🔍 내 서브넷 마스크를 2진수로 펼쳤을 때 1 인 비트와 0 인 비트가 각각 주소의 어느 부분을 가리키는지, 1 이 8개인 마디의 수를 근거로 설명하세요.
  - 답:

      서브넷 마스크에서 1인 비트는 네트워크(망) 부분이고, 0인 비트는 호스트(장비) 부분이다. 내 서브넷 마스크는 255.255.255.0이므로 앞의 세 마디에 각각 1이 8개씩 있다. 따라서 IP 주소 192.168.200.48에서 앞의 192.168.200은 망 부분이고, 마지막 48은 장비 부분이다.

- (나-2) 내 마스크에서 CIDR 숫자가 어떤 계산으로 나오는지 1 이 8개인 마디의 수를 넣어 설명하세요.
  - 답:

      255를 2진수로 바꾸면 11111111이므로 1이 8개이다. 내 서브넷 마스크는 255가 세 마디이므로 8 + 8 + 8 = 24가 된다. 따라서 CIDR은 /24이다.
      
- (나-3) 같은 교실의 다른 PC 와 비교했을 때, 망 부분과 장비 부분 가운데 어느 쪽이 같고 어느 쪽이 다른가요? 그렇게 되는 이유를 「같은 망」의 뜻과 이어서 설명하세요.
  - 답:
      같은 교실의 다른 PC가 나와 동일한 /24 네트워크에 연결되어 있다면, 앞의 세 마디인 192.168.200은 같고 마지막 장비 부분은 다르다. 같은 망에 속한다는 것은 서브넷 마스크를 적용했을 때 네트워크 주소가 같다는 뜻이다. 따라서 네트워크 부분은 같고, 각 PC를 구분하기 위한 장비 부분은 서로 달라야 한다.

- (다-1) 내 마스크를 기준으로 `192.168.10.25` 와 `192.168.20.25` 가 같은 망인지 판정하고, 비교해야 하는 마디를 짚어 근거를 설명하세요.
  - 답:
      내 서브넷 마스크는 255.255.255.0(/24)이므로 앞의 세 마디가 네트워크 부분이다. 두 IP 주소의 세 번째 마디가 각각 10과 20으로 다르기 때문에 네트워크 주소가 서로 다르다. 따라서 두 주소는 같은 망이 아니다.


- (다-2) 같은 두 주소를 `/24` 마스크로 판정하면 결과가 어떻게 달라지나요?
  - 답:
      내 PC의 서브넷 마스크가 이미 /24이므로 (다-1)과 결과가 같다. /24에서는 앞의 세 마디가 네트워크 부분이므로 세 번째 마디가 10과 20으로 다른 두 주소는 서로 다른 망이다. 반면 /16을 적용하면 앞의 두 마디인 192.168이 같으므로 같은 망으로 판정된다.


- (다-3) 마스크에 따라 판정이 달라진다는 사실이 통신 경로와 방화벽 규칙을 정할 때 왜 중요한지 설명하세요.
  - 답:
      서브넷 마스크에 따라 두 IP 주소가 같은 망인지 다른 망인지 달라진다. 같은 망이면 일반적으로 직접 통신하고, 다른 망이면 라우터를 거쳐 통신해야 한다. 따라서 마스크를 잘못 설정하면 통신 경로를 잘못 판단해 통신 오류가 발생할 수 있다. 또한 방화벽에서 허용하거나 차단할 IP 주소 범위도 달라지므로 정확한 마스크 설정이 중요하다.

### 문제 4-1 · 반으로 나누기 `/25`

- (가) 출력 두 줄:
                192.168.50.0/25
                192.168.50.128/25

- (나-1) 4.1 표와 맞춰 쓴 블록마다의 범위:
                1. 192.168.50.0/25: 192.168.50.0 ~ 192.168.50.127
                2. 192.168.50.128/25: 192.168.50.128 ~ 192.168.50.255


- (나-2) 블록 이름 `192.168.50.128/25` 의 `/` 앞 주소는 그 블록에서 어떤 주소인가요? 설명하세요.
  - 답:
      192.168.50.128은 두 번째 블록의 네트워크 주소이다. /25로 나누면 블록 하나에 128개의 주소가 들어가므로 첫 번째 블록은 .0~.127이고, 두 번째 블록은 .128~.255가 된다. 이때 .128은 두 번째 블록의 시작 주소이면서 해당 네트워크 전체를 나타내는 주소이므로 일반 장비에 할당하지 않는다.

- (나-3) 두 블록이 `.128` 에서 나뉘는 이유를 블록 하나의 주소 수로 설명하세요.
  - 답:
      /24 네트워크에는 총 256개의 주소가 있다. 이를 /25로 나누면 128개씩 2개의 블록이 만들어진다. 첫 번째 블록은 .0부터 .127까지이고, 두 번째 블록은 .128부터 .255까지이므로 두 블록의 경계가 .128이 된다.

- (나-4) 쓸 수 있는 수(126)만큼씩 자르면 안 되는 이유를 설명하세요.
  - 답:
       /25 블록 하나는 전체 128개의 주소로 구성된다. 이 중 첫 주소는 네트워크 주소, 마지막 주소는 브로드캐스트 주소이므로 장비에 사용할 수 있는 주소가 126개인 것이다. 서브네팅은 장비에 할당할 수 있는 주소 수가 아니라 전체 주소 수를 기준으로 나눠야 하므로 128개씩 나눠야 한다.

- (다-1) 4.1 첫 표의 `/26` 줄에서 읽은 주소 수 · 장비에 쓸 수 있는 수:
          
          전체 주소 수: 64개
          장비에 할당할 수 있는 주소 수: 62개

  - 답:

      기본 경로 `0.0.0.0/0`는 라우팅 표에서 다른 구체적인 경로와 일치하지 않는 목적지로 패킷을 보낼 때 사용한다. 내 PC에서는 기본 경로를 통해 기본 게이트웨이 `192.168.200.1`로 패킷을 전달한다.

- (다-2) 기본 경로의 `/0` 은 무엇을 뜻하나요?
  - 답:

      기본 경로 0.0.0.0/0에서 /0은 네트워크 부분을 0비트 비교한다는 뜻이다. 따라서 모든 IPv4 주소와 일치하며, 다른 구체적인 경로가 없을 때 사용된다.

- (다-3) 라우팅 표에서 기본 경로가 빠지면 맞는 줄이 없는 목적지로 가는 패킷은 어떻게 되나요?
  - 답:

      기본 경로가 사라지고 목적지에 일치하는 다른 경로도 없다면, PC는 패킷을 어디로 보내야 할지 알 수 없으므로 패킷을 버린다.

- (다-4) 이때 같은 망 통신과 인터넷 통신이 각각 어떻게 되는지 이유와 함께 설명하세요.
